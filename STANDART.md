# STANDART.md — стандарт семьи плагинов

Сведён 2026-11-09 по фактически построенным плагинам семьи
(`dsh-mailbox`, `dsh-rashod-live`, `dsh-packets-board`, `dsh-wave-gate-tool`)
на живом харнессе 0.2.2-rc.1. Каждый пункт — из кода репозиториев, а не из
головы; эталонные примеры указаны ссылками. Новое в семье начинается с
чтения этого файла; расхождение с живым харнессом решает инспекция
(`cordis_inspect_list` / `cordis_inspect_query`), а расхождение решает Мастер.

## 1. Репозиторий

- **Один плагин — один git-репозиторий** (`git init`, ветка `master`).
  Umbrella-каталог подключает каждый репо как **git-submodule** (слово
  Мастера 2026-11-09): umbrella фиксирует ссылку на коммит-эталон плагина
  (`git add <плагин>` после релиза), код остаётся в плагине. Новый плагин:
  `git init` внутри каталога → `git submodule add <абсолютный путь> <путь>`.
- Semver в `package.json`: `0.1.x` — заготовка, `0.2.0` — первая версия,
  проверенная прогоном на живом профиле, `1.0.0` — боевая ежедневка.
  Тег `vX.Y.Z` — на коммит релиза (эталон: `dsh-mailbox` `v0.2.0`).
- Коммиты по конвенции харнесса, по-русски: `feat|fix|docs(плагин): что`.
  **Перед КАЖДЫМ коммитом — зелёный `make check`.** Рабочее дерево к концу
  смены чистое.

## 2. Файловая структура (обязательный минимум)

```
<репо>/
├── package.json        # манифест бандла (§3)
├── cordis.patch.yml    # строка монтирования в профиль (§4)
├── index.js            # хост-часть (§5)
├── client.js           # только UI-плагин (§8)
├── Makefile            # check: bash scripts/check.sh
├── scripts/check.sh    # гейт сборки (§10)
├── locale/ru.json      # meta.title/description (§9)
├── locale/en.json
├── icon.svg            # своя векторная иконка
├── README.md           # что делает, как поставить, честный статус
├── ARCH.md             # принципы и контракты (меняется через комнату)
├── INTERNAL.md         # как устроено сейчас — в том же коммите, что код
├── SOUL.md             # фильтр решений плагина
└── CHANGELOG.md        # без вранья про статус (§13)
```

## 3. `package.json` — форма манифеста

Эталон: [dsh-wave-gate-tool/package.json](dsh-wave-gate-tool/package.json).

```json
{
  "name": "@local/dsh-<имя>",
  "version": "0.2.0",
  "private": true,
  "description": "одна строка по-русски, что делает",
  "type": "module",
  "exports": {
    ".": "./index.js",
    "./locale/*.json": "./locale/*.json",
    "./icon": "./icon.svg"
  },
  "files": ["index.js", "cordis.patch.yml", "locale/*.json", "icon.svg"],
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

UI-плагин добавляет `"./client.js": "./client.js"` в `exports` и `client.js`
в `files` (эталон: `dsh-packets-board`). **npm-зависимостей нет ни у кого**:
plain JS без transpile, только `node:*` — сборщик запрещён намеренно, он
становится долгом (правило семьи; проверка резолвится `scripts/check.sh`).

## 4. `cordis.patch.yml` — монтирование

Одна строка `insert` с рубильниками в `config`, комментарии — со ссылкой на
слово Мастера и дату (эталон: [dsh-mailbox/cordis.patch.yml](dsh-mailbox/cordis.patch.yml)):

```yaml
- insert:
    - id: <короткий-id>
      name: '@local/dsh-<имя>'
      config:
        root: /абсолютный/путь          # рубильники: путь, режим, лимиты
        enabled: true                    # включено словами Мастера 2026-11-05
```

- `config` — единственное место, откуда плагин берёт пути/режимы; плагин
  ничего не угадывает.
- Схема конфига на schemastery НЕ подключена (семейное «без зависимостей»);
  читаем защитно (§5).
- Правку самого патча профиля руками не делаем — только `install_bundle`.

## 5. `index.js` — контракт хост-части

Три обязательных экспорта (проверяются `check.sh`):

```js
export const name = 'dsh-<имя>'          // === имя пакета без scope @local/
export const inject = ['tools']          // нужные сервисы харнесса
export function apply(ctx, config = {}) { … }
```

- **Защитное чтение конфига**: обязательное поле отсутствует/пусто →
  `console.warn('[<имя>] config.<поле> не задан — плагин неактивен')` и
  `return`. Плагин без конфига не валит загрузку профиля
  (эталон: `apply` в rashod-live, wave-gate-tool).
- Ресурсы — через `ctx.effect(...)`; освобождение симметрично (интервалы,
  слушатели, children).
- **Отказ регистрации тула — громкий**: без `try/catch`, молчаливая пустота
  хуже падения (SOUL семьи; в wave-gate-tool 0.1.0 `catch` прятал
  гарантированный TypeError — исправлено в 0.2.0).
- Сбои фонового кода (таймеры, слушатели событий журнала) не роняют сессию:
  ошибка в `console.warn`, не наружу (rashod-live).
- События берём из живого журнала/инспекции, не на глаз: имена проверены
  замером (`turn/end`, `assistant/message → data.usage` — rashod-live).
- Инъекция в чужую сессию — полноценный `UserMessage`
  (`{id: uuid, role: 'user', content, source:{kind}}`), как делает сам
  харнесс (эталон: mailbox; прецедент cordis-host-runner).

## 6. Модель-facing инструменты (`ctx.tools.register`)

Обязательная форма по живому харнессу 0.2.2 (**без `output` регистрация
бросает TypeError — замер**). Эталон целиком:
[dsh-wave-gate-tool/index.js](dsh-wave-gate-tool/index.js#L84-L143).

- `description` говорит модели, что делать, включая смысл кодов возврата
  («exitCode!=0 — это ответ, а не ошибка инструмента»).
- `parameters` — JSON Schema, `additionalProperties: false`.
- `timeoutMs` — объявленный бюджет; исполнение **кооперативное**: слушаем
  `exec.signal` (политика TOOL_TIMEOUT ставит дедлайн по нему) + держим
  собственный страховочный `setTimeout`-убийцу.
- `output.schema` + `output.render` — обязательны; возвращаемое значение
  валидируется схемой при КАЖДОМ вызове, форма `execute` и схема должны
  совпадать буквально (замер: лишнее/недостающее поле отклоняется).
- Детерминированные коды: `-1` = «процесс не запущен или убит инструментом»
  (не выдуманный код самой программы), плюс хвост вывода с меткой отсечения
  — против молчаливой пустоты.
- Запуск бинарников — `spawn` с массивом аргументов и `cwd`, **без shell**.

## 7. Хост HTTP-роуты (если нужны)

`webServer.register` с **именованным** маршрутом (wildcard запрещён
харнессом); именованные роуты обслуживаются без отдельной авторизации —
это зафиксировано в ARCH.md packets-board и отражено в тексте ошибки UI.
Роут только отдаёт данные; решение о написании — за инструментом/хостом.

## 8. Клиентская часть `client.js` (UI-плагины)

Эталон: [dsh-packets-board/client.js](dsh-packets-board/client.js).

- `window.__ModuleLoader__.load({ id: '<тот же пакет>', factory(require) {…} })`.
- React берём `require('react')`, JSX нет — `React.createElement`.
- Слоты/типы вкладок и токены темы — **только по живой инспекции**
  (`Slots.listSubTree`, `Theme.listTokens`; токены `--dsw-alias-*` сверялись
  замером), не по догадке.
- Данные — `fetch` на роут хоста; обязательны состояния загрузки/ошибки и
  автообновление с очисткой таймера в `useEffect`.
- UI не пишет молча: кнопка → явное действие с подтверждением.

## 9. `locale/` + `icon.svg`

- `ru.json`/`en.json` содержат `meta.title`, `meta.description` — по-русски
  в `ru`, осмысленно в `en`; в `description` — для чего плагин мастеру.
- `icon.svg` — своя векторная иконка (64×64 viewBox, line-art), не заглушка.

## 10. `make check` — гейт

Шаблон: [dsh-mailbox/scripts/check.sh](dsh-mailbox/scripts/check.sh)
(+`node --check client.js` у UI-плагинов). Проверяет: синтаксис `index.js`;
импорт — наличие `apply`, совпадение `name` с репо, `inject` массивом;
JSON-валидность манифеста и локалей; непустую иконку; упоминание имени
пакета в патче. Плагин с тулами добавляет проверку наличия `output` в
определении. «Сборки» нет — это и есть сборка.

## 11. Установка и обновление профиля

- Только `plugin_manager install_bundle target=<абсолютный путь репо>`.
  **Обновление уже установленного — только через `remove_bundle` →
  `install_bundle`** (живое подтверждение: повторный install поверх не
  перекидывает версию; переустановка link-бандлов применяется сразу).
- Живой ли плагин — решает `list_plugins` (`fiberPhase: active`) и прогон
  функции, а не «строка появилась».
- Изменения конфига существующих строк до живой сессии не доходят (журнал
  сессии замороживает конфиг на старте) — это норма, не баг.

## 12. Бережность к живому

- Пишем только в явно отведённые конфигом пути; чужие сессии, чужие
  журналы, `РАСХОД.db` и репозиторий продукта — не трогаем.
- Токены/ключи — nowhere кроме credentials; в файлы плагинов не пишем.
- Новых типов событий в журнал сессии не вводим.

## 13. Честность (документация и отчёты)

- «Проверено» = прогнано своими руками (замер). Остальное — «оценка».
  Числа помечаются: замер/оценка.
- README/CHANGELOG не врут про статус: заготовка помечена заготовкой.
- Отчёт Мастеру: три блока (Сделано / Решилось / Нужно от хозяина), плохие
  новости первыми. Решения о включении, рестартах и боевом профиле — за
  Мастером.

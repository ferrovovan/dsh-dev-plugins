# dsh-dev-plugins — семейство самописных плагинов DeepSeek Harness

Создан 2026-11-05 словом хозяина. Здесь живут **самостоятельные git-репозитории
плагинов**, облегчающих workflow Помощника Мастера (пакеты `agents/П-NN`,
волны, почта, учёт токенов, приёмка, доски, словари фраз).

Каждый плагин — **отдельный репозиторий** (в зонтике он подключён как
git-submodule): своя версия (semver в `package.json`), свои теги, свой
`SOUL.md`, своя документация (`README.md`, `ARCH.md`, `INTERNAL.md`,
`CHANGELOG.md`), своя проверка (`make check`). Umbrella-каталог (это место) —
общая документация, правила семьи и CI-гейт; кода здесь нет.

Стандарт семьи обязателен: **[STANDART.md](STANDART.md)**. Указание агентам:
**[AGENTS.md](AGENTS.md)**. Roadmap: **ПЛАН-РАЗРАБОТКИ.md**.

## Как установить плагин (три шага)

Нужен запущенный DeepSeek Harness с профилем, в который ставишь.

**1. Клонировать зонтик и подтянуть плагины:**

```bash
git clone https://github.com/ferrovovan/dsh-dev-plugins.git
cd dsh-dev-plugins
# все доступные подмодули, по одному — недоступный не роняет остальные:
for p in $(git config -f .gitmodules --get-regexp '\.path$' | awk '{print $2}'); do
  git submodule update --init --depth 1 "$p" || echo "⊘ $p пропущен"
done
```

> На 2026-11-19 у `dsh-promt-studio` и `dsh-word-basket` репозиторий на GitHub
> ещё нет (коммиты живут локально) — они и будут «пропущены». После их
> создания и `scripts/push-all.sh` команда выше станет полной.

**2. Установить бандл — только через plugin manager** (он сам допишет
профиль; руками `cordis.patch.yml` профиля не правим):

*через GUI:* Настройки → Плагины → установить из папки → выбрать каталог
плагина (например `dsh-dev-plugins/dsh-mailbox`).

*или попросить агента:*

> установи бандл `/полный/путь/до/dsh-dev-plugins/dsh-mailbox`

под капотом — `plugin_manager install_bundle target=<абсолютный путь>`.

**3. Проверить, что живой, а не «строка появилась»:** `list_plugins`
(нужен `fiberPhase: active`) и фактический прогон функции плагина. Новый
бандл может активироваться через HMR; **замена уже установленного пакета
требует** `remove_bundle` → `install_bundle`, а изменение презетов/конфига
существующих строк доживает до сессии только после рестарта DSH.

### Конфиг — рубильники в строке профиля

Каждый плагин берёт пути и режимы **только** из `config` своей строки
(пример — `dsh-mailbox/cordis.patch.yml`: `root`, `role`, `targetSession`,
`enabled`, `limitPerHour`). Без обязательного поля плагин честно объявляет
себя неактивным в логе. Пути к твоим данным и включение/выключение —
решение хозяина, не плагина.

## Обновление

```bash
git pull
for p in $(git config -f .gitmodules --get-regexp '\.path$' | awk '{print $2}'); do
  git submodule update --init --depth 1 "$p" || echo "⊘ $p пропущен"
done
```

затем переустановка изменённых бандлов (`remove_bundle` → `install_bundle`).

## Как проверить (то же самое делает CI)

```bash
make check    # каждый плагин — своим scripts/check.sh
make family   # семейный стандарт по STANDART.md для всех подмодулей
```

`make family` проверяет: манифест (§3), обязательные файлы (§2), синтаксис и
контракт экспортов `index.js` (§5), валидность и чистоту от секретов
`cordis.patch.yml` (§4), полноту `locale/` и иконку (§9), упоминание версии в
`CHANGELOG.md` (§13), наличие `output{schema,render}` у регистрируемых тулов
(§6 — без него харнесс 0.2.2 бросает TypeError). Тот же прогон —
`.github/workflows/family.yml` на каждый push/PR и еженедельно.

## Как завести следующий плагин

1. Создать репозиторий на GitHub (`dsh-plugin-<имя>`), клонировать себя в
   подкаталог зонтика или `git init` внутри нового каталога.
2. Скопировать самый простой плагин (`dsh-wave-gate-tool`), переименовать
   пакет/строку/локаль/иконку, обнулить код до заглушки, первая запись
   `CHANGELOG.md` — `0.1.0 — заготовка`.
3. `git submodule add <url> dsh-<имя>` (+ `branch = main`, `ignore = all` —
   как у остальных), добавить в `REPOS` в `Makefile` и в таблицу выше.
4. `make family && make check` зелёные → коммит.

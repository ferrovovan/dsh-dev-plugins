## Правила ведения (обязательно, из SOUL семьи)

1. **Инспекция — арбитр.** Все имена API (`docs/РАЗРАБОТКА.md`) — снимок
   2026-11-05; перед использованием сверяй `cordis_inspect_list` /
   `cordis_inspect_query` (Service, Event, Config, Slots, Tool).
   Расхождение — правь РАЗРАБОТКА.md в том же коммите.
2. **Замер vs оценка.** Любое число с меткой природы. «Проверено» = было
   прогонено тобой; иначе — «оценка».
3. **Рубильники священны.** Плагины живут с `enabled: false`; включать
   `true` в конфиг-строке — только слово Мастера.
4. **Границы записи.** Пишешь: этот каталог; тестовые копии в
   `/home/vovan/Software/dsh-dev-plugins/.лаборатория/` (уже в .gitignore —
   не коммитить). Чтение боевого `~/Предприниматель/` — можно; правка —
   нет. `Mailbox/` и `РАСХОД.db` в тестах только копиями.
5. **Установка свои бандлов — разрешена** (реверсивна `remove_bundle`,
   дефолты выключены). Установка сторонних бандлов, включение `enabled:
   true`, рестарт DSH — нет: это меняет все сессии профиля; рестарт убьёт
   текущую сессию — вместо этого впиши в отчёт «требуется рестарт».
6. **Коммиты** на русском, `feat|fix|docs(плагин): что`, один логический
   шаг — один коммит; версия в `package.json` + строка `CHANGELOG.md`
   в том же коммите; тег `vX.Y.Z` — на релиз.
7. **Затруднение — начальству:** застрял на неизвестном API — не выдумывай,
   зафиксируй в INTERNAL.md с способом проверки и упомяни в отчёте.
8. `make check` (в корне — все репо) зелёный перед каждым коммитом.

## Этап 1 — `dsh-wave-gate-tool` → 0.2.0

Acceptance (всё на живом профиле, цифры в отчёт):
1. `install_bundle` репо → `Tool.listTools` содержит `wave_gate`.
2. Вызов `{action:"daemon", args:"status"}` → JSON `{ok, exitCode, output}`
   с живым выводом демона.
3. Вызов `{action:"verify", packet:"П-62"}` на сданном пакете → честный
   exitCode (красный на «чужом» диапазоне — ожидаемый факт, см. открытый
   хвост МОДЕРНИЗАЦИИ; зафиксировать какой).
4. Долгий прогон (~60 с) не убит политикой таймаутов; иначе — починить
   (`timeoutMs` определения / настройка политики) и записать в INTERNAL.
5. Реестр не требует `output` — или заявлен переход на `defineTool`
   (закрыть неизвестного №1).

## Формат отчёта Мастеру (после каждого этапа)

Три блока: **Сделано** (цифры: что прогонено, версии, коммиты), **Решено**
(что закрыто из неизвестных, на каком основании), **Нужно от хозяина**
(рестарт, слово на включение, выбор). Плохую новость — первой строкой.
Оценки помечать. Расход токенов — по указанию Мастера: в `РАСХОД.db`, в
отчётах не показывать (спросит сам).

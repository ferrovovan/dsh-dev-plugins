# Разработка плагинов харнесса — проверенные точки расширения

Всё ниже **проверено инспекцией живого харнесса** (`cordis_inspect_*`),
сырыми журналами сессий (`~/.dsh/sessions/**/session.v4.jsonl.zstd`) и
исходниками чекаута `~/Software/deepseek-harness` (версия 0.2.2-alpha.2)
2026-11-05. Перед доводкой перепроверяй: харнесс обновляется, имена могли
уехать. Природу правок помечать: (замер) — прогон на живом, (исходник) —
код чекаута, совпадающего с версией харнесса.

## Ограничение инспекции из GUI-сессии (замер 2026-11-05)

`cordis_inspect_query` с параметром `input` НЕ работает ни из этой
GUI-сессии, ни из дочерних (замер 5/5 + 8/8, детерминированно): вложенный
объект сериализуется в JSON-строку при сборке tool-call аргументов,
а валидатор метода (`packages/extensions/cordis-host-runner/
src/inspect-registry.ts:277`) отвергает строку («"input" must be an
object»). Обходных форм сериализации не найдено (исследование —
`.inspect-transport-test/REPORT.md`, не коммитить; отдельные ранние
сообщения об «успехе compact-JSON» не воспроизвелись и считаются
недостоверными). Что доступно:
- без `input` — catalog-режим: `Service.listService`, `Event.listEvents`,
  `Tool.listTools`, `Config.listConfigs` (1-я страница каталога; страниц
  дальше не достичь, offset живёт в input — полный каталог записей берите
  `plugin_manager list_plugins`, там offset/limit типизированы);
- точные контракты и типы — чтением исходников чекаута совпадающей
  версии и живых журналов;
- live-журналы сессий читаются напрямую: `zstd -dcf
  ~/.dsh/sessions/<workspace>/<session>/session.v4.jsonl.zstd`. В GUI
  сырые журналы — Session Inspector (`@deepseek-ai/dsh-experimental-
  inspector-profile`): пакет link-подключён к профилю, но в НАБОР живой
  композиции ещё не попал (запись `experimental-inspector` отсутствует
  среди 202 активных entries) — станет виден после рестарта; до рестарта
  — только zstd-файлы.

## Форма бандла

- `package.json` с `dsh.bundle.patch` (путь к YAML-патчу), `private: true`,
  `type: module`. Client-половина: экспорт `./client` + секция
  `dsh.client: { platform: "web", immediately: true, inject: [...] }`.
- Патч: `- insert: [ { id, name, config } ]`. Строка без `config` обязана
  его не требовать; конфиг строки читается плагином в `apply(ctx, config)`.
- `index.js` хоста: `export function apply(ctx, config) {}`, опционально
  `export const inject = ['tools', ...]`. Имена `inject` — точные ключи
  сервисов (см. ниже).
- Обязательные ресурсы отображения: `locale/ru.json`+`locale/en.json` с
  `meta.title`/`meta.description`, `icon.svg` (своя, ≤256 КиБ), всё в
  `exports` и `files`.
- **Без npm-зависимостей**: плагины семьи используют только `node:*`.
  Схемы `Config` (zod-подобный `@deepseek-ai/schemastery`) подключать
  только при доводке — там решается вопрос резолва зависимостей
  linked-бандла из профиля (см. INTERNAL.md любого плагина).

## Сервисы хоста (`ctx.<ключ>`, ключи проверены каталогом Service.listService, замер)

| ключ | зачем |
|---|---|
| `tokenMeter` | `measure(session)` → `{totalTokens, surfaceTokens, baseline:{kind,tokens,usage?}, ...}`; `contextPressure(session)` → `{pressureTokens, contextWindow}`. Оценка, не биллинг |
| `sessionProjections` | `register({key, apply(state,event), view(), stateVersion})` — свёртка журнала сессии; `stateOf`/`snapshot` — чтение |
| `tools` | `register(definition, options?)` — модель-facing тулы; `guard()` — синхронные отказы; `restrict()`. **`definition` обязан нести `output: {schema, render}` — без него register синхронно бросает TypeError (исходник index.ts:128–136, закрытие UNKNOWN №1 волнового гейта); `output.schema` — подмножество JSON Schema: type/oneOf/properties/required/additionalProperties/items/enum/const (+описания). `timeoutMs` в определении — опциональный кооперативный бюджет: не объявлен → политика `dsh-tool-call-timeout-policy` дедлайн НЕ ставит; объявлен → инструмент обязан слушать `exec.signal`. Возвращает disposer; привязывать к жизни плагина через `ctx.effect`** |
| `agents` | `get(sessionId)`, `list()`, `roots()` |
| `agentTeams` | `listMembers(agent)`, `listTasks(agent)`, `membership(agent)` |
| `subagents` | `listChildren(parentSessionId)`, `interrupt`, `sendMessage` |
| `webServer` | `register({kind:'exact'|'prefix', path, handler(req,res)})` — HTTP-роуты GUI-носителя |
| `workingDirectory` | `get(session)` — эффективная директория сессии |
| `configEditor` | персист конфигурации строки: `edit(ctx.fiber.entry, current => ({...}))` |
| `commands` | `register(definition)` — человек-facing slash-команды |
| `timer` | disposable timeout/interval/throttle |
| `fs` | абстракция файловой системы харнесса (для инструментов агентов); плагину обычно хватает `node:fs` |

## События хоста (Event.listEvents, релевантное)

- `agent/created` `{agent, source}` — навешивать пер-агентное поведение на
  `agent.ctx` (регистрировать в `agent.ctx.effect(...)`, disposer держать
  и у себя).
- `agent/turn-stopping` `{agent, turn, signal}` — конец хода; `agent/status`
  `idle ⇄ running`; `agent/disposed`.
- `session/event` `(this: Scoped<Session>, session, event)` — пост-коммитный
  поток событий журнала (режим emit; каталог Event.listEvents, замер).
  Строки durable-событий закрыты замером живых журналов 2026-11-05
  (UNKNOWN №1 rashod-live — закрыт):
  - закрытие хода: `type:"turn/end"`,
    `data:{turn, reason:{kind:"completed"}}`, при отмене —
    `data:{turn, reason:{kind:"aborted", reason:{kind:"user"}}}`;
  - ответ ассистента: `type:"assistant/message"`,
    `data:{turn, step, message, usage, stream}`, где
    `usage:{inputTokens, outputTokens, totalTokens}` — это биллинг-usage
    (для rashod-live: `kind:"замер"` доступен из потока событий, не только
    из `tokenMeter`);
  - рядом в потоке: `turn/start`, `step/start`, `step/end`, `tool/call`,
    `tool/result` (замер по двум журналам).
- `tools/result`, `tools/pre-execute`, `tools/post-execute` — обёртки
  диспетча; `session/flush` — чекпоинт durable.
- **Нельзя**: добавлять события с новым `type` в журнал сессии
  (`ignorable` не выставить; сессия потом не откроется).

## Client-слоты GUI (Slots.listSubTree, живой профиль)

- Правый сайдбар: сервис `sidebarRightTabs` (`register({id, kind,
  priority:'extension', title()})`) + keyed-слоты `sidebar.right.pane.tab`
  и `sidebar.right.pane.tab.title` (key = `id` определения). Навигация —
  сервис `sidebarRight` (`openTab/openResource`).
- `conversation.composer.dock` — амбиентные строки под композером.
- `ctx.slots.inject(ownerSlot, () => ctx.slots.register({name, id|key,
  order}, Component))` — регистрация с автосбором.
- React — из браузерной таблицы модулей: `const React = require('react')`
  в factory; `window.__ModuleLoader__.load({ id: <имя пакета>, factory })`.
- Стилизация — только токены `--dsw-alias-*` (Theme.listTokens).

## Правила практики (references/practices.md, канон)

- Единственный источник истины — журнал сессии; память плагина — кэш.
- Пер-агентное — на `agent.ctx` из слушателя `agent/created`.
- Методы будки агента (исходник `dsh-agent/src/runtime-types.ts`,
  закрытие UNKNOWN №2 mailbox): `inject(message: UserMessage)` — контекст
  в следующий pre-step **без пробуждения**; `followup(message)` — новый ход
  с пробуждением; `steer(message)` — на ближайший шаг;
  `send(message, target, wakeup)` — низкий уровень. Аргумент — **объект
  `UserMessage`**, не строка. `AgentStatus = 'idle' | 'running'`
  (закрыт unknown №3 packets-board: поле есть; событие `agent/status`
  подтверждено каталогом Event.listEvents).
- Будит агента только `agent.followup()`; `agent.inject()` — кладёт в
  inbox без пробуждения.
- Водяные слушатели без права решения возвращают `next()`.
- UI-операции и агентские тулы вызывают **один и тот же метод** хоста
  (user-actions.md); действия власти (одобрение) остаются человеческими.

## Контракт пользователя (наш,_Master's contract, 2026-11-05)

- «Почта»: у получателя — право снизить порог, пауза, полное отключение
  (инструменты `mailbox_*` + конфиг строки).
- Учёт токенов — в **промежуточный файл**, в `РАСХОД.db` только якорем
  (принцип П-69). Плагин в БД не пишет.
- Волну/гейт плагин только запускает и показывает; решения принимает
  Мастер.

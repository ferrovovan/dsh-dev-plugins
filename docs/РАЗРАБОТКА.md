# Разработка плагинов харнесса — проверенные точки расширения

Всё ниже **проверено инспекцией живого харнесса** (`cordis_inspect_*`) и
исходниками чекаута `~/Software/deepseek-harness` 2026-11-05. Перед доводкой
перепроверяй: харнесс обновляется, имена могли уехать.

## Форма бандла

- `package.json` с `dsh.bundle.patch` (путь к YAML-патчу), `private: true`,
  `type: module`. Client-половина: экспорт `./client` + секция
  `dsh.client: { platform: "web", immediately: true, inject: [...] }`.
- Патч: `- insert: [ { id, name, config } ]`. Строка без `config` обязана
  его не требовать; конфиг строки читается плагином в `apply(ctx, config)`.
- `index.js` хоста: `export function apply(ctx, config) {}`, опционально
  `export const inject = ['tools', ...]`. Имена `inject` — точные ключи
  сервисов (см. ниже).
- Обязательные ресурсы отображения: `locale/ru.json`+`locale/en.json` с
  `meta.title`/`meta.description`, `icon.svg` (своя, ≤256 КиБ), всё в
  `exports` и `files`.
- **Без npm-зависимостей**: плагины семьи используют только `node:*`.
  Схемы `Config` (zod-подобный `@deepseek-ai/schemastery`) подключать
  только при доводке — там решается вопрос резолва зависимостей
  linked-бандла из профиля (см. INTERNAL.md любого плагина).

## Сервисы хоста (`ctx.<ключ>`, ключи проверены Services.list)

| ключ | зачем |
|---|---|
| `tokenMeter` | `measure(session)` → `{totalTokens, surfaceTokens, baseline:{kind,tokens,usage?}, ...}`; `contextPressure(session)` → `{pressureTokens, contextWindow}`. Оценка, не биллинг |
| `sessionProjections` | `register({key, apply(state,event), view(), stateVersion})` — свёртка журнала сессии; `stateOf`/`snapshot` — чтение |
| `tools` | `register(definition, options?)` — модель-facing тулы; `guard()` — синхронные отказы; `restrict()` |
| `agents` | `get(sessionId)`, `list()`, `roots()` |
| `agentTeams` | `listMembers(agent)`, `listTasks(agent)`, `membership(agent)` |
| `subagents` | `listChildren(parentSessionId)`, `interrupt`, `sendMessage` |
| `webServer` | `register({kind:'exact'|'prefix', path, handler(req,res)})` — HTTP-роуты GUI-носителя |
| `workingDirectory` | `get(session)` — эффективная директория сессии |
| `configEditor` | персист конфигурации строки: `edit(ctx.fiber.entry, current => ({...}))` |
| `commands` | `register(definition)` — человек-facing slash-команды |
| `timer` | disposable timeout/interval/throttle |
| `fs` | абстракция файловой системы харнесса (для инструментов агентов); плагину обычно хватает `node:fs` |

## События хоста (Event.listEvents, релевантное)

- `agent/created` `{agent, source}` — навешивать пер-агентное поведение на
  `agent.ctx` (регистрировать в `agent.ctx.effect(...)`, disposer держать
  и у себя).
- `agent/turn-stopping` `{agent, turn, signal}` — конец хода; `agent/status`
  `idle ⇄ running`; `agent/disposed`.
- `session/event` `(session, event)` — пост-коммитный поток событий
  журнала: здесь durable-события `turn/end`, `assistant/message`,
  `tool/result` (точные строки `event.type` проверять инспекцией —
  это UNKNOWN №1 для rashod-live).
- `tools/result`, `tools/pre-execute`, `tools/post-execute` — обёртки
  диспетча; `session/flush` — чекпоинт durable.
- **Нельзя**: добавлять события с новым `type` в журнал сессии
  (`ignorable` не выставить; сессия потом не откроется).

## Client-слоты GUI (Slots.listSubTree, живой профиль)

- Правый сайдбар: сервис `sidebarRightTabs` (`register({id, kind,
  priority:'extension', title()})`) + keyed-слоты `sidebar.right.pane.tab`
  и `sidebar.right.pane.tab.title` (key = `id` определения). Навигация —
  сервис `sidebarRight` (`openTab/openResource`).
- `conversation.composer.dock` — амбиентные строки под композером.
- `ctx.slots.inject(ownerSlot, () => ctx.slots.register({name, id|key,
  order}, Component))` — регистрация с автосбором.
- React — из браузерной таблицы модулей: `const React = require('react')`
  в factory; `window.__ModuleLoader__.load({ id: <имя пакета>, factory })`.
- Стилизация — только токены `--dsw-alias-*` (Theme.listTokens).

## Правила практики (references/practices.md, канон)

- Единственный источник истины — журнал сессии; память плагина — кэш.
- Пер-агентное — на `agent.ctx` из слушателя `agent/created`.
- Будит агента только `agent.followup()`; `agent.inject()` — кладёт в
  inbox без пробуждения.
- Водяные слушатели без права решения возвращают `next()`.
- UI-операции и агентские тулы вызывают **один и тот же метод** хоста
  (user-actions.md); действия власти (одобрение) остаются человеческими.

## Контракт пользователя (наш,_Master's contract, 2026-11-05)

- «Почта»: у получателя — право снизить порог, пауза, полное отключение
  (инструменты `mailbox_*` + конфиг строки).
- Учёт токенов — в **промежуточный файл**, в `РАСХОД.db` только якорем
  (принцип П-69). Плагин в БД не пишет.
- Волну/гейт плагин только запускает и показывает; решения принимает
  Мастер.
